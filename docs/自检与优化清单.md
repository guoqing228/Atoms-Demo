## 1. 完成度（功能完整性 / 稳定性 / 工程质量）

**已完成并有证据**

- 核心闭环：生成 → 实时预览 → 多轮迭代 → 版本回滚 → 分享 → 导出 → 刷新恢复，
  见 `scripts/e2e-flows.mjs`（11 项断言全过，含控制台零报错）。
- 13 个内置应用 + 通用 CRUD 合成器全部通过自动化验收：`node scripts/check-recipe.mjs --all`
  （生成 → 文件/语法/外链检查 → 无头浏览器渲染 → 文本量/可交互元素/横向溢出/对比度 → 截图）。
- 真实模型接入：OpenAI 兼容与 Anthropic 两条流式协议均实现，并用本地假 SSE 服务做过端到端验证
  （`scripts/test-real-provider.mjs`，2/2 PASS）。**缺口：尚未用真实 Key 验证生成质量。**

**本轮补上的稳定性/可用性短板**

- 生成过程可**取消**（AbortController，随时停止，不再只能干等 5–10s）；
- 失败/中断后提供**「重试这一步」**，不用重新输入；
- 生成期间 UI 状态明确（按钮禁用 + 停止按钮 + 步骤时间线）；
- Git 仓库 + `.gitignore` + `.gitattributes` + CI（typecheck/build）+ LICENSE；
- 依赖自包含（项目内 `pnpm-workspace.yaml` + `pnpm-lock.yaml`），换机器/上 CI 可复现。

**仍缺**

- 无真实模型 Key 的生成质量评估集（固定 prompt + 人工/自动打分）；
- 无单元测试（目前是集成/验收测试为主）；
- 生成任务并发上限与速率限制（部署后需要，防滥用）。

## 2. 工程思维（任务拆解 / 技术选型 / 复杂度控制 / 取舍）

**做得好的地方**

- 先定**事件协议**（`step/log/plan/file/done/error`），Mock 与真实模型都实现同一个
  `AsyncGenerator<AgentEvent>`，前端只消费事件流 → 换模型、加 provider 不需要动 UI；
- Mock 生成器是**确定性的**（路由 + 调色板 + 设计语言 + 静态自检），所以能写自动化验收；
  这比"返回假字符串"工程价值高一个量级；
- 刻意控制复杂度：无登录、无服务端数据库、单进程无队列；用 IndexedDB + URL 编码分享替代后端；
- 预览选择「多文件内联 + srcdoc + 运行时桥」而不是部署独立站点，用最小复杂度换来秒级预览。

**需要改进的工程债（按严重度）**

1. `src/components/workspace/workspace.tsx` 约 700 行，承担了状态编排 + 持久化 + 分享/导出 + 快捷键，
   应拆成 `useProjects` / `useGeneration` / `useShare` 三个 hook（纯重构，不改行为）；
2. 真实 provider 的 `<plan>/<file>` 标签解析用正则增量扫描，模型不守协议时容错有限；
   更稳的做法是 JSON 结构化输出（OpenAI `json_schema` / Anthropic tool use）；
3. 预览 iframe 目前 `allow-same-origin`（为了让生成应用能用 localStorage），
   生产环境应改为独立 origin（`*.vibeforge.app`）彻底隔离；
4. 分享链接 ≈ 11.7KB（完整应用 lz-string 编码），超出多数 IM 的可点击长度；
   可用 `CompressionStream`（gzip+base64url）压缩到 ~5KB，或改为「短链 + 服务端存储」；
5. 无 lint 规则集（只有 tsc），建议加 ESLint + `no-explicit-any` 等。

## 3. 用户体验（交互清晰 / 流程顺畅 / 是否可用）

**已做**

- 三栏工作台：项目 → 对话（Agent 过程可见）→ 预览（浏览器外壳 + 视口切换）；
- 生成中显示步骤、逐文件写入、自检日志；完成后自动切换到预览；
- 代码 / 控制台 / 版本三个 tab，控制台会真实捕获生成应用的 `console` 与未捕获错误；
- 空状态、加载骨架、Toast 反馈、快捷键（⌘K 新建、⌘↵ 发送）、375px 可用；
- 本轮：**整体字号放大**（正文 13→14、辅助 10.5→11.5、代码 12.5→13.5，对话宽度 396→420）、
  生成可取消、失败可重试。

**仍缺**

- 移动端 Chat / Preview 只能上下堆叠，缺少「对话 ↔ 预览」切换（当前 46vh 各自滚动）；
- 分享对话框只给长链接，缺少「体积提示 + 生成短链/导出 HTML」的分流引导；
- 无生成进度百分比（只有步骤状态）；长任务无预计耗时提示；
- 无「深色模式」（按需求保持亮色，可作为可选项）；
- 高亮文本/链接的无障碍语义可以更完整（部分 icon 按钮已有 aria-label）。

## 4. 创新性（亮点 / 独特视角 / 可扩展潜力）

**亮点**

1. **Agent 过程可视化**：不是"转圈等待 → 出结果"，而是把拆解、计划、写文件、自检逐帧呈现；
2. **运行时桥**：预览 iframe 里的 console / 未捕获错误会回流到工作台控制台 —— 这是后续
   「让 Agent 看着报错自己修」的数据基础；
3. **确定性 Mock**：同一 prompt 稳定复现，让生成结果可做回归测试，且没有 Key 也能完整体验；
4. **设计语言引擎**：prompt → 调色板 + 排版/圆角/装饰，13 个应用各有独立信息架构，不是一套模板换色；
5. **分享即运行**：整个应用编码进 URL，零后端、零部署。

**下一个真正拉开差距的点**

- **自动修复闭环**：把 iframe 捕获的错误作为下一轮输入 → Agent 定位并 patch → 复检，
  形成「生成 → 运行 → 观察 → 修复」的飞轮（Mock 用确定性规则，真实模型用 LLM）；
- 一键部署生成结果到用户自己的域名（静态站点 + 自定义域），把 Demo 变成可交付工具。
